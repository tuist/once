# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Breaking Changes

- Script actions now live under `[[target]]` with `kind = "script"` and
  `[target.script]`. Existing `[[task]]` entries must be migrated to the new
  form before upgrading.
- Inline script targets now use the same public contract names as annotated
  script files: `input`, `output`, `env`, and `cwd`.

### Added

- Native [Bazel](https://bazel.build) workspace integration. Once detects a
  Bazel workspace from `MODULE.bazel`, runs `bazel query` to enumerate every
  rule, and exposes each one as a `bazel_target`, `bazel_test`, or
  `bazel_binary` in the graph. Building a target reads its action graph
  through `bazel aquery` and runs every action itself from a shadow
  execution root under `<workspace>/.once/bazel-shadow/<target>/`; Bazel
  supplies analysis and external-repository download, Once supplies
  execution. When the graph contains a Bazel-internal action with no argv
  in `aquery` output (`Symlink`, `FileWrite`, `RunfilesTree`,
  `SymlinkTree`, `RepoMappingManifest`), the target falls back to
  `bazel <capability>` and records the unsupported mnemonics on its
  provider so the gap is visible. A new `once bazel` compatibility surface
  accepts single-label `bazel build` and `bazel test` invocations, routes
  them through the Once graph, and forwards every other invocation to the
  system `bazel` unchanged. See the
  [Bazel guide](https://buildonce.dev/docs/guide/graph/bazel) and the
  [`bazel_workspace`](https://buildonce.dev/docs/reference/prelude/bazel_workspace)
  reference.
