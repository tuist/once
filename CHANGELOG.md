# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Breaking Changes

- Once is now Struo. The `once` command, `once.toml`, `.once/`, `# once`
  script headers, `ONCE_*` environment variables, `once_*` MCP tools, crates,
  and SDK packages are renamed to `struo`, `struo.toml`, `.struo/`,
  `# struo`, `STRUO_*`, `struo_*`, and `buildstruo`. The site moves to
  [struo.run](https://struo.run).
- Script actions now live under `[[target]]` with `kind = "script"` and
  `[target.script]`. Existing `[[task]]` entries must be migrated to the new
  form before upgrading.
- Inline script targets now use the same public contract names as annotated
  script files: `input`, `output`, `env`, and `cwd`.

### Added

- Native [Bazel](https://bazel.build) workspace integration. Struo detects a
  Bazel workspace from `MODULE.bazel`, runs `bazel query` to enumerate every
  rule, and exposes each one as a `bazel_target`, `bazel_test`, or
  `bazel_binary` in the graph. Building a target reads its action graph
  through `bazel aquery` and runs every action itself from a shadow
  execution root under `<workspace>/.struo/bazel-shadow/<target>/`; Bazel
  supplies analysis and external-repository download, Struo supplies
  execution. When the graph contains a Bazel-internal action with no argv
  in `aquery` output (`Symlink`, `FileWrite`, `RunfilesTree`,
  `SymlinkTree`, `RepoMappingManifest`), the target falls back to
  `bazel <capability>` and records the unsupported mnemonics on its
  provider so the gap is visible. A new `struo bazel` compatibility surface
  accepts single-label `bazel build` and `bazel test` invocations, routes
  them through the Struo graph, and forwards every other invocation to the
  system `bazel` unchanged. See the
  [Bazel guide](https://struo.run/docs/guide/graph/bazel) and the
  [`bazel_workspace`](https://struo.run/docs/reference/prelude/bazel_workspace)
  reference.
- Optional `--sound` global flag that plays a continuous evolving cinematic
  pad while a command runs actions. A musical fingerprint is derived from
  the verb and target, so the same command always sounds like the same
  piece; cache hits ring a bell chord, fresh actions land a brass stab,
  failures thump low, and the whole run resolves into a swelling chord
  before a slow release. Off by default; headless environments silently
  degrade to a no-op. See
  [The Sound of Your Build](https://struo.run/docs/guide/local-execution/sound).

### Fixed

- Concurrent builds protect overlapping output trees during execution,
  cleanup, and cached restoration, including uncacheable actions. A directory
  replacement can no longer delete another action's output during capture;
  sibling outputs still build concurrently.
