# Deferred local-hit optimization ideas

- Do not cycle sampling policies again without a new profile or workload. Standalone attempts failed; after parallel barrier startup, three paired comparisons were inconsistent and favored readiness-gated sampling by only about 0.35 ms on average. The current composition remains, but no strong sub-millisecond gain is established. Preserve sampling and signal behavior for actual streaming runs.
- Do not repeat reporting configuration deduplication on the current fixture: runs 33 and 41 failed, including a quieter retry. For much larger manifests, consider invocation-owned typed metadata rather than process-global stale configuration caches.
- Do not disable TLS roots merely because a discovery URL uses HTTP. An HTTPS proxy can still require TLS verification. Pinned reqwest 0.13 uses `tls_certs_only`, not the older `tls_built_in_root_certs` API. Any discovery-client startup optimization must preserve platform root trust and HTTPS proxy support.
- Receipt/tracker validation and event preflight remain the measured hot path, roughly 7.75 ms and 4.20 ms respectively. The wrapper contributes roughly 7.32 ms and is off limits. Argument parsing and logging setup cost only 0.037 ms and 0.286 ms in sampled startup traces. Historical graph allocation ideas do not necessarily affect receipt hits.
- Source-digest position lookup reads all cache bytes even when only the schema and journal position are needed. Run 30's allocation-skipping deserialization did not improve the 12 KiB fixture. For genuinely large workspaces, evaluate streaming deserialization to bound memory and measure latency explicitly.
- Consider a lazy TLS platform verifier for discovery only if client construction is proven dominant. Preserve platform trust, HTTPS proxy verification, redirect policy, and normal HTTPS behavior. A custom verifier adds dependencies and substantial correctness-sensitive complexity, so do not pursue it based on this HTTP fixture alone.
- Normal full-graph cache hits with the public tracker-disabled fallback take about 155 to 164 ms, much slower than receipt hits. The workspace loader evaluates the full built-in schema set even for a small custom-kind workspace. Profile that evaluation before considering a bounded, recoverable typed-contract cache under `.once/`, keyed by module sources, executable identity, workspace ownership and all relevant observations. Preserve schema, native discovery, example ownership and validation diagnostics. This may help fallback hits but is not known to improve the primary receipt-hit workload.
- A generic native-marker selection index could let workspace discovery load only relevant built-in families. This would require a deliberate Starlark module contract change, documentation and portability tests, with no ecosystem-specific Rust branches. Do not infer absent native projects from explicitly declared targets alone.
