# Deferred local-hit optimization ideas

- Move host sampling to connected event reporting only if a future profile shows sysinfo initialization meaningful. Run 29 reduced work but regressed median from 29.62 to 30.19 ms, so it was discarded. Signal integration tests passed.
- Reuse resolved infrastructure configuration across graph dispatch and live preflight instead of reparsing once.toml for account, project, endpoint, and authentication. Avoid process-global stale configuration caches; pass invocation-owned typed metadata. Run 33 removed 52 net lines but measured 43.89 ms during heavy host noise, so it needs a stable paired retry before keeping.
- Do not disable TLS roots merely because a discovery URL uses HTTP. An HTTPS proxy can still require TLS verification. Pinned reqwest 0.13 uses `tls_certs_only`, not the older `tls_built_in_root_certs` API. Any discovery-client startup optimization must preserve platform root trust and HTTPS proxy support.
- Profile receipt validation separately from process parsing and live preflight. Current logs show approximately 4 ms event preflight and 7 ms receipt/tracker checks. The benchmark now often reuses build receipts rather than full graph analysis, so historical allocation experiments do not necessarily affect the current hot path.
- Source-digest position lookup currently reads all cache bytes even when only the schema and journal position are needed. If allocation-skipping deserialization helps, evaluate streaming deserialization to bound memory for very large workspaces, with latency tradeoffs explicitly measured.
